# nuScenes trainval — diversity statistics & curation notes

Statistics derived from the **full v1.0-trainval** metadata (10 keyframe archives,
850 scenes, 34,149 lidar keyframes). Generated by
[scripts/analyze_nuscenes_diversity.py](../scripts/analyze_nuscenes_diversity.py).

Outputs:

- [data/scene_stats.csv](data/scene_stats.csv) — all 850 scenes with per-axis tags
- [data/curated_v1_scenes.txt](data/curated_v1_scenes.txt) — 255-scene picks (token, name, part, location, vehicle, description)
- [data/curated_v1_tokens.json](data/curated_v1_tokens.json) — token list for direct consumption

The 10 keyframe archives (`v1.0-trainval01..10_keyframes.tgz`) each contain exactly
**85 scenes** in contiguous log order. Scene → part mapping was recovered by
clustering the inode `ctime` of each scene's `samples/CAM_FRONT/*.jpg` files
(each archive was extracted in a separate `tar` invocation, so its files share a
tight ctime cluster). 850/850 scenes mapped.

### SurroundOcc voxel GT — local availability

Path: [data/nuscenes_occ/nuscenes_occ/samples/](../data/nuscenes_occ/nuscenes_occ/samples/)

- **34,149 .npy files** — one per lidar keyframe, matches sample count exactly.
- Format: sparse voxel list, `shape=(N, 4)`, `dtype=int64`,
  columns `(x_voxel, y_voxel, z_voxel, class_id)`.
- `class_id` range `0..16` (0 = noise / free space, 1..16 = SurroundOcc classes).
- Example file: `n008-2018-05-21-11-06-59-0400__LIDAR_TOP__1526915243047392.pcd.bin.npy`
  → 22,716 occupied voxels; histogram on this single sample:

  ```
  {0: 117, 4 (car): 4151, 7 (ped): 105, 10 (truck): 1663,
   11 (drive): 4293, 12 (other_flat): 59, 13 (sidewalk): 770,
   14 (terrain): 764, 15 (manmade): 7571, 16 (vegetation): 3223}
  ```

This means class-balanced curation (max-min coverage of all 16 classes per scene)
is fully implementable without further downloads. Per-sample voxel counts can be
aggregated to per-scene counts, then scenes scored by rarity-weighted entropy.

### Tarball shards uploaded to HF

[data/nuscenes_occ_shards/](../data/nuscenes_occ_shards/) contains four
`surroundocc-00{0..3}.tar.zst` shards plus `manifest.json` — these were uploaded
to Hugging Face by [scripts/upload_surroundocc_to_hf.py](../scripts/upload_surroundocc_to_hf.py)
(commit `305ad5a`). The local `.npy` tree above is the source of truth for
analysis; the shards exist only to make the GT redistributable.

### Notes & caveats

- **Thing counts are box instances** (one row per annotation, including the same
  object across multiple frames). For per-scene unique instance counts, group by
  `instance_token` instead — the script counts annotations because that's the
  right signal for "how often does the model see this class in this scene".
- **Stuff counts are voxels summed across all lidar keyframes** in the scene,
  not unique voxels. A scene with more samples and more nearby surface will
  dominate; normalise by `n_lidar_samples_seen` (column in the CSV) for fair
  per-frame comparison.
- **Unmapped nuScenes categories** (don't map to any SurroundOcc class):
  `animal`, `movable_object.pushable_pullable`, `movable_object.debris`,
  `static_object.bicycle_rack`. These are silently dropped — correct behaviour
  given the SurroundOcc taxonomy.

## 7. Next steps (not yet implemented)

1. **Class-balanced curation** — re-run the curator with an objective that
   maximises **min per-class instance/voxel coverage** across the 255-scene
   subset, using `class_composition_per_scene.csv` as input. Likely picks change
   significantly for trailer / const_veh / bus / bicycle / motorcycle / other_flat.
2. **Richer description tags** — add `intersection`, `crosswalk`, `jaywalker`,
   `bus`, `cones`, `barriers`, `bump`, `narrow`, `bridge`, `overtake`, `nature`.
3. **Per-instance density** — group annotations by `instance_token` for unique
   counts; pair with annotation-count-per-sample for a continuous traffic-density
   signal that replaces the binary `busy` tag.
